A config file has two readers.

One settings file, written as JSON and as TOML, edited one line at a time. After each edit, twenty real parsers read it, ten per format, and each one shows what it heard. Every count on screen was measured on the exact bytes shown.

How it was made

The method comes from Prompt Motion, a gallery of 234 motion videos made with Claude Opus 5.5, each shown with the prompt behind it, and from its analyses of what the best-received prompts share.

  1. A brief in the gallery’s own structure.

    Inputs, direction with a banned list (no glows, crossfades, bouncy easing or text in the corners), a structure on a 90 BPM beat grid, a build recipe, gotchas, and a start step. It adds the two things the gallery’s explainer study found almost every prompt leaves out: who the video is for, and an accuracy rule.

  2. Measured before drawn.

    Every snippet went through the harness behind What the Parser Hears: the same 10 JSON and 10 TOML parser configurations at pinned versions. The page reads its verdicts from that output; none is typed by hand.

  3. Reviewed before rendering.

    A desk check caught a send that fired before the TOML file had finished typing. One still per scene beat, laid out on a contact sheet, caught four layout problems, all fixed before the full render.

  4. One HTML page, rendered frame by frame.

    Every frame is a pure function of time. Playwright drives headless Chrome through all 6,080 frames, ffmpeg encodes them, and the soundtrack is written in code with the Web Audio API.
